# How the public Clicky code works

Inspected on 11 October 2026. Source snapshot: commit [a80fa80721a8aebe51a170a7780705024ebc6e46](https://github.com/farzaa/clicky/commit/a80fa80721a8aebe51a170a7780705024ebc6e46). This note explains the public original. Farza's README update dated 27 April 2026 says newer development is private and directs users to HeyClicky. The public source cannot establish how the latest installed app works. [README](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/README.md#L1-L20)

## What Farza assembled

Clicky combines a native Mac application with existing AI services. SwiftUI renders the interface, AppKit supplies the menu bar and floating windows, AVAudioEngine captures microphone audio, ScreenCaptureKit takes screenshots, AssemblyAI transcribes speech, Claude interprets the question and images, and ElevenLabs makes the spoken reply. The running application coordinates these pieces through CompanionManager. This is visible in the app's entry point, manager-owned clients, audio capture, and HTTP requests. [Application entry point](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/leanring_buddyApp.swift#L10-L54), [Manager-owned services](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L65-L85), [Audio capture](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/BuddyDictationManager.swift#L514-L559), [Screenshot capture](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionScreenCaptureUtility.swift#L81-L100), [Claude request](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/ClaudeAPI.swift#L112-L156), [Speech synthesis](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/ElevenLabsTTSClient.swift#L33-L67)

There is no model-training pipeline in the inspected app. Its active AI behavior comes from API calls to pre-existing providers. The custom work is the Mac integration, prompt design, audio and response lifecycle, coordinate conversion, and animated companion. This conclusion follows the complete active response path and proxy code, rather than a claim about all private development. [Response pipeline](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L586-L711), [Worker](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/worker/src/index.ts#L19-L141)

## One interaction, step by step

1. Hold Control + Option. The global shortcut causes CompanionManager to show the companion, dismiss its panel, cancel the previous reply, stop speech playback, and start microphone dictation. The configured shortcut is Control + Option. [Shortcut setting](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/BuddyDictationManager.swift#L95-L98), [Shortcut response](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L473-L535)

2. AVAudioEngine supplies microphone buffers to the transcription provider. The default configuration selects AssemblyAI. The app first obtains a temporary token from the Cloudflare Worker, then connects directly to AssemblyAI's WebSocket service. Its audio becomes 16 kHz PCM16, with the request selecting the u3-rt-pro speech model. Audio does not travel through the Worker. [Default transcription configuration](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/Info.plist#L11-L12), [Provider selection](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/BuddyTranscriptionProvider.swift#L45-L71), [Token retrieval](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/AssemblyAIStreamingTranscriptionProvider.swift#L19-L80), [WebSocket and audio](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/AssemblyAIStreamingTranscriptionProvider.swift#L111-L205), [Speech model and encoding](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/AssemblyAIStreamingTranscriptionProvider.swift#L437-L468)

3. Release the shortcut. Dictation stops microphone capture, asks for a final transcript, and retains a timed fallback so the interaction can finish if the final callback does not arrive. The final transcript callback sends the question into the Claude pipeline. [Dictation finalization](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/BuddyDictationManager.swift#L476-L537), [Transcript submission](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L513-L525)

4. Clicky takes screenshots after transcription completes. It captures each connected display, excludes its own windows, orders the cursor's display first, and creates JPEG images with a longest side of 1280 pixels and compression quality 0.8. It labels images with their dimensions and display identity. This is a screenshot per interaction, rather than a continuously sent screen-video feed in this path. [Capture timing and labels](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L586-L617), [Screen capture implementation](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionScreenCaptureUtility.swift#L38-L121)

5. Clicky sends the current images, the transcript, the system prompt, and recent conversation to Claude through the Worker. The default model is Sonnet 4.6. ClaudeAPI requests streamed text, but the active manager ignores incremental text chunks and waits for the complete reply. [Model default](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L110-L117), [Request content](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/ClaudeAPI.swift#L112-L156), [Manager stream handling](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L608-L626)

6. Clicky separates the words to speak from an optional pointing instruction, updates the animated companion, and asks ElevenLabs to synthesize the words. ElevenLabsTTSClient selects eleven_flash_v2_5, waits for the MP3 response with URLSession.data, then plays it through AVAudioPlayer. Despite its opening comment about streaming playback, this implementation receives the whole audio response before playback. [Response and pointing](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L625-L704), [Actual audio implementation](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/ElevenLabsTTSClient.swift#L33-L67)

## The pointing trick

Claude's prompt asks it to append a compact tag such as `[POINT:285,11:source control]` or `[POINT:400,300:terminal:screen2]`. The numbers refer to pixels in the screenshot, with the origin at the top left. The visible reply remains conversational speech; the tag supplies coordinates to the application. The prompt also specifies a warm lowercase voice, short default answers, screen-specific guidance, and no spoken code blocks. [System prompt](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L544-L576)

A regular expression reads the tag. The manager chooses the correct display, clamps the coordinate, scales image pixels to Mac screen points, flips the vertical axis, and adds the display's global origin. This is how it handles resized screenshots, Retina displays, and multiple monitors. [Tag parser](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L782-L825), [Coordinate conversion](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L638-L677)

The blue triangle lives in a transparent NSWindow that cannot become the focused window and ignores mouse events. The flight animation updates the triangle's drawing position at approximately 60 frames per second along a Bezier arc, lasting 0.6 to 1.4 seconds depending on distance. It also rotates and scales the triangle. This code moves the drawn companion, rather than the operating system's actual mouse pointer. [Overlay window](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/OverlayWindow.swift#L14-L52), [Flight implementation](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/OverlayWindow.swift#L495-L567)

My interpretation is that this small text protocol is a central product idea. Claude supplies the explanation and a location in the same reply; native application code supplies the pointing experience. It requires no separate model training or autonomous action loop in the active path. [Prompt and protocol](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L561-L576), [Active reply processing](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L613-L677)

## What the public version can do

The inspected path is a voice assistant that sees screenshots, explains what it sees, and points. It does not implement a general autonomous agent that clicks through applications or performs a sequence of computer actions. The active Claude request contains images and text without tool definitions, and the result handler interprets a POINT tag to animate the overlay. [Active request](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/ClaudeAPI.swift#L112-L148), [Active reply handler](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L613-L711)

An alternative ElementLocationDetector file uses Anthropic's computer-use tool declaration and extracts coordinates from a tool_use response. I found no call sites that instantiate this detector in the Swift sources. Even its response parser only returns a CGPoint; it does not execute a click. The file's presence should therefore not be taken as evidence of an active autonomous computer agent. [Alternative detector](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/ElementLocationDetector.swift#L150-L207), [Coordinate parser](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/ElementLocationDetector.swift#L235-L263). Call-site check: `rg 'ElementLocationDetector\(' leanring-buddy --glob '*.swift'` returned no matches in this snapshot.

Conversation memory is a Swift array in the manager, capped at ten exchanges. Prior exchanges contain text; only the current message includes images. This path does not establish durable long-term memory. [In-memory history](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L83-L85), [History limit](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L684-L694), [Message construction](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/ClaudeAPI.swift#L115-L140)

The public source also sends the user transcript and assistant reply to PostHog analytics. This is observable behavior of the published code, not a claim about the latest private HeyClicky app. [Analytics initialization](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/leanring_buddyApp.swift#L40-L43), [Transcript and reply analytics](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/ClickyAnalytics.swift#L82-L95)

## The small backend

The Cloudflare Worker is a TypeScript proxy with three routes. POST /chat forwards to Anthropic and passes the streamed response through. POST /tts forwards to ElevenLabs. POST /transcribe-token requests an AssemblyAI token that lasts 480 seconds. Provider keys reside in Worker environment secrets. The Mac app is published with placeholder proxy URLs that a developer must replace for their own deployment. [Worker routes](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/worker/src/index.ts#L12-L38), [Claude proxy](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/worker/src/index.ts#L51-L79), [Temporary token](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/worker/src/index.ts#L82-L106), [TTS proxy](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/worker/src/index.ts#L109-L140), [App proxy configuration](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionManager.swift#L71-L80), [Setup instructions](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/README.md#L52-L82)

The entire Worker source is 141 lines. It does not include account authentication, billing, a database, or a general tool-execution service. Those features cannot be assumed from the latest product's interface or from this public proxy. [Complete Worker source](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/worker/src/index.ts#L1-L141)

## What took custom engineering

The product-specific code handles permission prompts, global shortcut events, cancellations when the user interrupts, microphone buffer conversion, partial and final transcript timing, screenshots that exclude Clicky itself, display coordinate mapping, click-through windows, and companion animation. These are the pieces that turn several APIs into one Mac experience. [Permissions and cancellation](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/BuddyDictationManager.swift#L377-L458), [Transcript timing](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/BuddyDictationManager.swift#L476-L559), [AssemblyAI finalization](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/AssemblyAIStreamingTranscriptionProvider.swift#L273-L374), [Capture and display mapping](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/CompanionScreenCaptureUtility.swift#L38-L121), [Overlay](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/OverlayWindow.swift#L14-L52), [Animation](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/OverlayWindow.swift#L495-L567)

OpenAI and Apple Speech providers exist as alternatives. The factory chooses a provider from configuration and isConfigured checks. In this snapshot AssemblyAI's isConfigured returns true even though its endpoint is a placeholder. This means the mere presence of fallback implementations does not prove automatic recovery when an AssemblyAI network request fails. [Provider factory](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/BuddyTranscriptionProvider.swift#L45-L98), [AssemblyAI configuration](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/AssemblyAIStreamingTranscriptionProvider.swift#L19-L28)

## Dependencies, tests, and release tooling

The resolved Swift dependencies include Sparkle 2.9.0, PostHog 3.47.0, and PLCrashReporter 1.12.2. The Worker package uses Wrangler for local development and deployment. [Swift dependency lock](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved#L3-L30), [Worker package](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/worker/package.json#L1-L11)

The unit-test file contains three tests about permission presentation and screen-recording permission state. The UI tests mostly launch the app and measure launch performance. These files do not establish end-to-end verification of transcription, Claude, TTS, or coordinate accuracy. No build or tests were run for this research. [Unit tests](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddyTests/leanring_buddyTests.swift#L11-L38), [UI tests](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddyUITests/leanring_buddyUITests.swift#L25-L39)

A release script archives with Xcode, creates a DMG, submits Apple notarization, staples the ticket, signs a Sparkle update, and publishes a GitHub release. However, its configuration still names makesomething and julianjear/makesomething-mac-app. Sparkle startup is commented out in the app entry point. This is evidence of included release tooling, not proof that this script or automatic updates ship the latest Clicky. [Release configuration and archive](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/scripts/release.sh#L34-L46), [Archive command](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/scripts/release.sh#L146-L154), [Notarization and publishing](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/scripts/release.sh#L205-L249), [Updater disabled at startup](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/leanring-buddy/leanring_buddyApp.swift#L45-L54)

## What the repo establishes about AI coding tools

The README recommends using Claude Code to clone, configure, run, and extend the project. AGENTS.md supplies architecture and implementation instructions for AI coding agents and identifies CLAUDE.md as its symlink. That proves the repo supports an AI-assisted development workflow. It does not prove which tool wrote each module, how much code Farza personally authored, how long development took, or what percentage an AI generated. [Claude Code setup workflow](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/README.md#L22-L38), [Agent instructions](https://github.com/farzaa/clicky/blob/a80fa80721a8aebe51a170a7780705024ebc6e46/AGENTS.md#L1-L24)

The working clone was shallow at inspection, so its single locally visible README-update commit was not treated as a full development history. We did not inspect private repository history. The code explains the implementation; it does not by itself reconstruct the creator's entire process.
